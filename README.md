# A 股及 ETF 行情与网格研究台

基于 FastAPI、React、DuckDB、SQLite 和 Parquet 的本地中文研究工作台，支持沪深 A 股及场内 ETF 各周期行情管理、股数网格回测、固定股数定投和参数研究。界面按 1920×1080 桌面设计，并在当前电脑 3120×2080 显示器的 1560×1040 逻辑分辨率下检查；“行情”“数据管理”“策略回测”“参数研究”“结果分析”为独立页面。回测与研究各自保留草稿，通过明确操作传递配置；临时进度显示在右下角，任务历史和结果入口位于顶部任务中心。服务默认只监听 `127.0.0.1`；行情、配置、任务和结果保存在本机。

正式 ETF 行情固定来自 `data/dataset/etf`，股票数据包预留为 `data/dataset/stock`。旧格式快照、演示数据、旧结果、旧迁移入口和旧配置兼容均已移除；当前数据目录只保留 v5 研究结果和当前股数回测结果。

“ETF 研究”提供独立的网格适用性评分、统计诊断与参数建议，默认扫描自选 ETF 并自动回放前 10 个合格标的的有限候选。区间质量不足时可显式运行本地批量校验；研究冻结行情和辅助资料版本，保留样本内标签，并支持历史复现及后续回测草稿。方法与接口见 [ETF 研究说明](docs/etf-research.md)。

## 启动

Windows 需要 Python 3.12、`uv`、Node.js 和 npm。直接双击 `start.cmd` 或运行：

```powershell
.\start.ps1
```

启动脚本执行 `uv sync --frozen --python 3.12`，在构建缺失或前端源码、构建配置有更新时执行 `npm ci` 和 `npm run build`，然后启动服务并打开浏览器。默认地址为 <http://127.0.0.1:8000>，API 文档为 <http://127.0.0.1:8000/docs>。

### 计算资源

默认按可用逻辑核心数的 **75%** 自动分配计算线程；本机 16 核对应 12 个线程。两个研究任务同时运行时会在分块边界重新平衡额度。下载默认并发 4，BaoStock 日线批处理最多两个独立会话，本地校验最多 4 个独立月份进程，矩阵阶段默认最多 8 线程。任务工作集默认 8 GiB，用于缩小分块或排队。

“行情 → 数据维护与本机设置”可以切换自动或指定 CPU 上限，并调整下载并发、校验进程、矩阵线程和工作集预算；修改在后续任务生效。`GET /api/v1/performance` 返回有效预算与当前租约。当前实现使用 CPU 多核与矩阵优化，不启用 GPU 后端。

行情同步只请求所需新浪未复权分钟数据，不再额外请求前复权日线；BaoStock 会话在批处理进程内复用。未变化且校验账本完整的区间直接复用结果，不重新扫描行情正文。

运行后可通过顶栏“重启项目”重新加载后端、依赖和前端构建。确认后服务会受控关闭并由 `restart.ps1` 重新运行标准启动脚本；运行中的任务会被中断，排队任务在服务恢复后继续，启动日志写入 `.local/restart.log`。

手动安装、构建和启动：

```powershell
uv sync --frozen --python 3.12
Push-Location frontend
npm ci
npm run build
Pop-Location
uv run --frozen stockregression serve --open-browser
```

## 首次全市场同步与后续更新

证券目录来自 AKShare 的股票清单、新浪 ETF 清单与数据包已有证券资料。日常任务只更新数据包中已有证券；需要加入新证券时必须使用明确的初始化任务（脚本参数 `-Initialize` 或页面中的显式选项）。目录操作不会自动加入自选，包内证券更新也不会刷新全市场清单。

交付脚本 `sync-market.ps1` 默认更新数据包内已有证券的日线和 1 分钟，下载并发为 4。日线先于 1 分钟执行；5/15/30/60 分钟、周线和月线由本地基础行情按需聚合：

```powershell
# 仅预检范围，不下载行情
.\sync-market.ps1 -DryRun

# 首次全市场日线历史；结束后安装盘后日线与 1 分钟增量计划
.\sync-market.ps1 -Mode history -Frequency 1day -StartDate 2015-01-01 -Initialize -InstallSchedule

# 中断后继续：跳过相同指纹已经完成的标的
.\sync-market.ps1 -Mode history -Frequency 1day -StartDate 2015-01-01 -Initialize

# 更新已有证券的日线和 1 分钟增量
.\sync-market.ps1 -Mode daily

# 只抓取近期 1 分钟窗口；更早历史须先登记数据包或导入文件
.\sync-market.ps1 -Mode repair -Frequency 1min -StartDate 2026-09-28

# 显式执行日线缺口修补
.\sync-market.ps1 -Mode repair -Frequency 1day -StartDate 2026-01-01

# 忽略恢复检查点，重新核对全部目标；内容未变化的记录仍按指纹和时间去重
.\sync-market.ps1 -Mode daily -Fresh
```

预检不会创建行情任务。正式 ETF 数据使用 schema 2 年/月分片目录，SQLite 只保存可重建索引。导入、同步、修订和按需聚合都发布不可变分片，并由数据集版本清单确定当前可见文件；同一包搬迁不改变身份，旧代际任务快照不会自动读取新数据。

旧版整包迁移、校验和索引维护命令：

```powershell
uv run stockregression data migrate-package --source D:\ETF --target .\data\dataset\etf --dry-run
uv run stockregression data migrate-package --source D:\ETF --target .\data\dataset\etf --apply
uv run stockregression data verify-package --full
uv run stockregression data rebuild-index
```

正式任务在开始逐标的下载前显示目标数量和可用空间。日线、1 分钟状态、合规截止日期和逐日校验结果分别持久化；任务中心显示当前处理阶段、已核验日数、目标计数和实际资源配置，不据此承诺总耗时。瞬时网络错误最多重试一次，协议错误直接报告并回退，可取消、从失败／取消／部分完成状态继续，也可仅重试失败项。继续操作会沿用原任务冻结的范围和截止日，并创建新任务记录；原任务保留终态。

日线全历史初始化会先建立历史账本，逐段检查目标证券覆盖；它与只回看近期交易日的日常增量不同。账本检查按最多 512 个交易日为一批，完成校验后原子发布该批；中断报告会保留已处理批次及成功、失败、复用、跳过和未处理计数，不能把取消任务当作全量完成。增量下载只请求已发布行情尾部之前 3 个自然日到冻结截止日；历史账本缺失、落后或中断时，从本地分片补校历史，保持完整质量要求，不扩大网络下载范围。

长期停止交易的基金通过证券退市日期永久排除，不进入全市场更新目标。本地清理可运行 `uv run python scripts/purge_stale_funds.py --older-than-days 365 --apply`；脚本会先标记退市，再删除对应日线和分钟数据集、分片、质量文件及基本资料行。证券清单刷新和数据包重建也会跳过这些标记，避免旧基金被重新带回同步范围。

等价 CLI 及小范围同步：

```powershell
uv run --frozen stockregression data sync --frequency 1day --scope market --mode history --start 2015-01-01 --resume
uv run --frozen stockregression data sync --frequency 1day --scope market --mode incremental --resume
uv run --frozen stockregression data sync --frequency 1min --mode repair --symbol 600000.SH --start 2026-09-28 --end 2026-10-16
uv run --frozen stockregression data sync --frequency 1min --scope watchlist --mode incremental --resume
uv run --frozen stockregression data probe --source tdx --capability recent_minute --market all
uv run --frozen stockregression data probe --source eastmoney --capability etf_daily --market etf
```

不指定代码或范围时使用自选列表。CLI 会输出进度和报告 JSON 路径；部分目标失败退出码为 2，全部失败为 1，逐标的原因仍保留。API `/api/v1/data/sync-status` 提供同步任务记录、当次日线/分钟截止日期和分页，完整报告保存在 `results/`；这些历史任务记录不代表后来导入或合并后的当前完整性，当前状态见 `/api/v1/data/coverage/{symbol}`。

### 数据来源和实际覆盖

股票与 ETF 使用同一套来源治理。BaoStock 提供股票和 ETF 的未复权日线、交易日历及股票公司行动；ETF 日线默认也使用 BaoStock。AKShare 的新浪分钟接口提供近期 1 分钟行情，ETF 分红和拆分资料来自 AKShare。5/15/30/60 分钟、周线和月线由本地基础数据生成。东方财富 ETF 日线与通达信近期分钟可直接选择；ETF 日线可通过 `market_data.etf_daily_fallback_enabled`（默认开启）允许东方财富备用源。失败会记录具体接口和错误类别；网络或接口级故障按配置冷却，单标的空响应不触发整个来源冷却。手动检测仅供诊断，不作为来源选择或回退的前提。近期分钟在新浪和通达信均失败，或某交易日覆盖明显不完整时，才尝试同花顺；同花顺不提供 ETF 日线回退。

**1 分钟历史行情只从当前数据包读取，不再从 Hugging Face 或其他在线历史库下载。** 页面中的 1 分钟历史初始化入口已移除；更早的分钟记录需要通过数据包登记、文件夹导入或单文件导入补齐。线上增量与缺口修补只覆盖新浪或同花顺接口实际返回的近期窗口，超出窗口的缺口继续保留为待导入，不会被误报为已补齐。同花顺没有逐分钟成交额字段，系统按成交量与 OHLC4 估算后再按当日官方成交额缩放；OHLC 和成交量保持来源原值。

“全市场任务完成”表示已处理目标目录，不代表每只证券都有完整历史分钟线。来源可能限流或暂时不可用；实际日期、标签、量纲、日线降级、分红核验和缺口以同步报告与质量日历为准。打开数据管理页只读取来源健康缓存，不会主动联网；需要复测时提交“检测”任务，结果在任务完成后共享给后续所有任务。

上述来源限制是接口的能力记录。标的当前是否齐备，以本地合并后的数据为准：行情、回测、参数研究统一展示当前校验结果和手动导入／接口同步的实际区间；已补齐数据不会继续继承旧下载失败提示。深市收盘集合竞价的零量估值占位与真实分钟缺口分别统计，已有本地数据完整时不为这些占位重复下载。详见[分钟质量规则](docs/data-format.md#分钟质量核验与回测降级)。

## 行情页面

“行情”提供自选、代码/名称搜索、股票/ETF 筛选、K 线和成交量。支持日线及 1/5/15/30/60 分钟、缩放、十字光标、加载更早行情；默认 MA5、MA10、MA20、MA60，修改逗号分隔的周期后离开输入框即可生效，留空关闭。均线包含展示区间之前的足够数据，翻页不会重新从零计算。

提供更新当前证券、更新自选和数据包内已有证券的快捷入口。任务完成后刷新本地行情和覆盖状态；完整导入、初始化、质量报告、存储与计划位于“数据管理”。行情浏览与严格回测校验分离：未核验价格可查看并带有来源说明；回测不会把未核验分钟当成可靠路径。

## 股数回测与定投

新配置保存为 `schema_version=3`。默认初始持股 1000、最低持股 0、最高持股 2000，每次买入、卖出和定投 100；最高持股可以留空，表示不限制数量。ETF 使用“份”；仓位与交易计量均为整数数量。所有数量按 100 递增，正交易量至少 100，科创板买入和定投至少 200；最低 ≤ 初始，填写上限时还须满足初始 ≤ 最高。

初始持股表示开始前已经拥有的股份，按开始前最近有效交易日收盘价估值，首日即可卖出，不虚构建仓成交或建仓费用。固定可用现金预算已删除。期初现金为零；成功买入所需金额超过现有现金时只补足差额，拒单和撤单不补款。卖出回款与已到账股息优先复用。成交继续受交易资格、实际可用现金、持股数量上限、费用、价格限制和 T+0/T+1 约束。

选择标的后，默认截止日取该标的当前周期的本地数据末日（分钟周期使用 1 分钟基础数据，日线周期使用日线），开始日按原有约一年窗口定位。日期控件显示含首尾的交易日数量，可拖动滑块或输入数量调整开始日；显式载入及手动填写的日期会保留。改变标的或开始日期会读取**开始日期之前**最近的本地有效交易日收盘价并显示所属日期；可手工修改网格参考价，初始持股估值仍采用历史收盘价。缺少行情或前置历史时，预览、正式回测和参数搜索返回具体缺口，不会自动下载，也不使用区间内未来价格代替估值。结束日期保留用户填写值，同时显示实际截止和滞后提示；补数后仍无有效区间则停止计算。

所有网格模式都分别使用买入间距和卖出间距：参考价下方按买入间距形成买入网格，上方按卖出间距形成卖出网格。固定网格要等价格真正跨过参考价下方一个买入间距才触发首次买入，上方同理等待一个卖出间距。移动网格比较当前价与最近成交价，等差和等比固定网格比较价格相对参考价所在的网格。固定网格的相邻成交信号还必须距上一笔实际成交至少一个完整间距，避免价格在同一网格线附近反复穿越时产生 0.1% 级别的买卖循环。佣金默认 `0.05%`（内部 `0.0005`），最低佣金默认 `0.1` 元，支持连续输入小数。这两个字段的有效修改会自动记入本机设置，重启、新建或重置时填充上次值；载入已保存配置采用该配置的费用，载入动作不覆盖个人记忆。

“策略回测”和“参数研究”共用本机记住的默认设置，但切换页面时各页保留当前草稿；显式点击“用当前配置研究”或载入研究候选才会更新另一页配置。刷新或重启时标的留空，点击输入框显示最近提交过回测或参数研究的 10 个去重标的，包含失败或取消的已提交任务；输入代码或名称后切换为证券搜索。网格规则、仓位与交易量、定投设置、参数研究设置与完整搜索范围的有效编辑会自动记入本机设置，跨标的共用。空输入和无效中间值不会覆盖上次有效值；载入已保存配置或研究候选不会改写个人记忆。“恢复上次参数”恢复四组记忆、清空标的并使用新的默认日期；“恢复默认范围”仅重置并记忆研究搜索范围。

定投支持独立初始仓位、每天／每周／每月频率和每期股数。初始仓位默认 0 股／份，按开始前最近有效收盘价认定期初投入，不虚构建仓费用，也不占用首期定投。之后每期在首个可成交交易日开盘独立投入指定数量所需金额及手续费，不从网格现金扣款；整期无法成交时记录跳过，不跨期补投。

全仓持有使用独立的期初 1000 股／份、零现金账户，按开始前收盘价认定投入，不产生首日建仓交易。它不受网格初始资金、持股上下限、网格参考价和步长影响；股息留在账户内，不追加外部投入。

```text
资产投入比 =（当前现金 + 持仓市值 + 应收权益）÷ 累计投入
累计盈利 = 当前资产总值 − 累计投入
收益率曲线 = 累计盈利 ÷ 周期峰值净投入
```

工作台和结果分析将网格交易、同资金被动持有、全仓持有和定投放在同一张本金收益曲线图中，纵轴为百分比，盈亏平衡线为 `0%`。外部本金为初始持股估值加累计成功买入补款，内部卖出回款和分红不增加本金；整段收益统一为期末累计盈利除以本次评价区间的外部本金峰值。最大本金回撤按引擎逐 bar 的累计盈利峰值计算，而不是用日线展示抽样代替。外部本金峰值为零时收益和回撤为空并显示不可评价原因。持股数量图仅展示网格策略。

有效参数停止修改 600ms 后自动预览。预览复用正式成交内核、锁定数据快照并缓存行情预处理，只返回每日曲线和摘要；同页仅保留最新待算参数，旧响应不会覆盖新曲线。计算期间标明旧曲线状态，预览不生成永久任务或结果，只在本地已有数据就绪时开始。“运行回测”保存完整成交、拒单及快照，详细曲线、交易明细和导出在“结果分析”。

计算前先检查请求区间、前置估值收盘、交易日历、目标周期和公司行动资料。API 返回 `DATA_NOT_READY` 及结构化缺口，页面提供“去准备数据”入口；提交数据任务后才会联网。严格回测要求目标周期质量覆盖本次请求；分钟数据不完整时仍可浏览，但不会把不完整分钟伪装成可执行策略。缺少必要日线、日历或公司行动资料时同样停止计算，已验证的可用行情保留供以后复用。新数据通过质量检查后发布不可变快照，计算锁定该快照。

当前回测只接受 `schema_version=3` 的股数配置；旧现金/比例配置和转换入口已移除。旧研究结果同样已从当前项目数据和界面移除，重新运行 v5 研究才会生成可查看、可补算的结果。

## 参数研究

新版统一使用 `protocol_version=5`、`strategy_version=5`、`ranking_mode=robust_j` 和 `result_schema_version=2`，普通股数回测输入继续使用 `schema_version=3`。旧研究请求明确返回 422；旧结果文件和数据库任务已在本次结构清理中删除，当前结果列表只包含可读取的 v5 研究。

研究保留买入间距、卖出间距、每次买入和每次卖出四个执行字段，间距与份额可分别选择统一，对应 2、3 或 4 个独立参数，固定为等比网格与自然持仓：最低持仓 0，最高持仓不限。买卖比例仅由股数除以初始持股派生；实际持仓上限作为回测后的风险资格与 J 惩罚，不提前截断成交。训练只使用一段连续窗口，内部验证窗数量为 0。

参数研究可显式引用一条 ETF 研究结果作为冻结来源，请求字段为 `source_etf={result_id, candidate_ids?}`，并分别填写 `prior_policy` 与目标行情 `requested_data_version`。来源只提供相对的买卖间距和股数候选，原 ETF 的绝对价格上下界、参考价及来源数据版本不会复制到目标；目标仍使用自己的行情版本。来源截止日必须不晚于目标决策日，未来来源不会进入静态候选。来源缺失或候选不属于该结果时请求直接失败，不会自动改用最新结果或其他 ETF。

`prior_policy=off` 保持原研究顺序。`daily_state_v1` 使用决策日之前最多 250 个连续日线交易日，以 NATR14、HV10/HV60、ADX14 和 20 日振幅 Q75 形成最多 `min(8, 20%*training_budget)` 个先验起点；它只改变有限初始候选，不改变 J、约束或样本外口径。诊断记录配额、来源检查、转换结果和每个跳过原因。Hurst、IV、BBW 与冷却不在本轮。

`training_window_mode=same_price` 为默认模式：只用于选窗的历史高低价会按截至决策锚日已生效的公司行动转换到同一价格基准，再严格执行 `low < anchor < high` 并优先选择最远匹配日；无匹配时回退到配置上限。`fixed` 模式要求完整固定窗口。成交账本仍使用真实未复权价格。缺少必要前收盘价、无效除权因子或未支持行动时返回明确数据问题。

J、收益展示和超额收益统一使用峰值本金口径。网格与每个候选自己的 `matched_funding_hold` 在同一时间、因同一实际成交收到相同外部补款；对照账户用含费用的最大合法整手买入，整手余款留作后续重试，现金分红保留在账户内。基础超额是两者峰值本金收益率的差值，J 的中心收益、邻域均值和下行风险都使用该超额。最大风险约束改为 `max_principal_drawdown`，默认 20%，按引擎逐 bar 的盈利路径计算。

固定参数和季度自适应方案都使用真实连续样本外账本，换参不重置资金和持仓。`fixed` 与 `current` 使用评估开始日前同一个决策锚，`current` 复用这次固定选择并独立展示，不读取评估结束日重选；自适应分支才在每次生效日前使用当时可见历史。本版本不提供峰值本金超额收益的显著性检验，因此不显示 p 值、bootstrap 区间或正负显著性标签。费用压力只作诊断。

任务预算覆盖训练、邻域、峰值核验、展示补算、费用压力和样本外回放。展示预算默认 1000 且单独设上限；总评价数和运行时间在提交时冻结，缓存命中不重复计费。预算截断时保留已完成结果并明确标记不完整。结果读取不触发补算；缺失邻域通过后台 `research_completion` 任务生成独立修订。补算要求原数据版本、配置、源码、依赖锁和收益口径一致。

完整公式、来源时间因果、状态和存储契约见[参数研究协议 v5](docs/parameter-research-v5.md)。ETF v4 的 `market_state` 只增加日线诊断，不改变 GSS 或原回放，见[ETF 研究说明](docs/etf-research.md)。本机同价/固定窗口对比使用锁定快照与相同预算，结果见[训练窗口对比原始记录](docs/v5-training-window-comparison.json)；三 ETF 先验开关对照已在 ADX/NATR golden 修复后完成。550 日回看包含 368 个可用共同交易日，正式评估只取最后 250 日（2025-09-18 至 2026-09-30）；六个分支均未找到合格参数，实验说明见[研究先验对照实验](docs/research-priors-comparison.md)，原始结果见[这里](docs/research-priors-comparison.json)。

## 自动更新计划

默认周一至周五 **18:30** 先更新数据包中已有证券的**日线**，再更新已有 **1 分钟**数据，周六 **10:00** 修补日线缺口，使用真实交易日历和实际已收盘日期取数。新证券需要明确提交初始化任务；1 分钟历史只从本地数据包或导入文件建立。时间可在“数据管理”或“行情”的本机设置中编辑。网页关闭后 Windows 任务仍可运行。

```powershell
uv run --frozen stockregression schedule install
uv run --frozen stockregression schedule status
uv run --frozen stockregression schedule remove
```

安装会注册 `StockRegression-Daily` 与 `StockRegression-Weekly`，以当前 Windows 登录用户交互身份运行、隐藏启动窗口、错过时尽可能补执行、同一任务不重复启动。无人登录的服务账户场景未配置。`status` 返回应用保存的设置；系统实时执行状态请在 Windows 任务计划程序查看。保存已启用计划的新时间会重新注册任务。

## 导入和本地目录

正式基础周期只有 **1min、1day**；其余周期从二者按需聚合并持久化。数据包中的历史分钟文件直接按标的读取，日线从集中文件按代码过滤，新增和修订写增量分片；DuckDB 负责字段映射、时间过滤和缓存，SQLite 保存可重建索引、逐日校验与合规截止。“数据管理”页按证券展示各周期、文件、覆盖、合规和归档状态，并提供数据包登记、单文件与文件夹批量导入、线上基础周期更新、新证券初始化、准备任务、按需聚合和任务报告。完整说明见[周期行情数据管理](docs/market-data.md)。

本地文件导入只读取指定的日线或 1 分钟文件，不自动联网补齐其他周期。缺少日历、日线状态或时间标签依据时，记录先入库并标记待核验。回测、预览和参数研究只读取本地数据；缺少粗周期时自动从基础数据生成，基础数据不足时返回明确的准备范围和入口。

```powershell
uv run --frozen stockregression data import-file --frequency 1day --path .\imports\1day\600000.parquet --calendar-path .\calendar.csv
uv run --frozen stockregression data import-folder --frequency 1min --dry-run
uv run --frozen stockregression data sync --frequency 1day --mode incremental --scope watchlist
uv run --frozen stockregression data aggregate --symbol 600000.SH --from 1day --to 1week
```

“行情”的辅助区域和独立“数据管理”页支持本机 CSV / Parquet 导入。单文件与文件夹批量入口都不自动联网，只接受日线和 1 分钟；缺少日线、日历或标签依据时先入库并标记待核验。

数据管理页可以直接选择文件、选择文件夹、选择多个文件，也可以拖入文件或文件夹；批量入口会保留相对路径并显示待导入列表。ETF 数据包登记只读取原始文件的元数据，不复制 K 线。

```powershell
uv run --frozen stockregression data import-file 600000.SH --frequency 1day --path .\daily.csv --actions-path .\actions.csv --calendar-path .\calendar.csv
uv run --frozen stockregression data import-file 600000.SH --frequency 1min --path .\minute.csv --calendar-path .\calendar.csv --label-convention end
uv run --frozen stockregression data import-file 518880.SH --frequency 1day --path .\etf-daily.csv --etf-category commodity --calendar-path .\calendar.csv
```

`data import-file` 要求明确周期，ETF 类型可明确指定 `stock/bond/crossborder/commodity/money`；股票无需填写。准确字段、时区与质量规则见[数据文件格式](docs/data-format.md)。没有日历文件时导入仍可完成，但质量状态会标记待核验，不能用普通工作日列表替代真实日历。

默认应用目录为 `data/`，行情数据包按资产类型存放在其下的 `dataset/etf/` 和 `dataset/stock/`；当前活动 ETF 数据包为 `data/dataset/etf/`。索引、任务、结果和日志位于 `data/` 的其他子目录，行情 Parquet 正文只放在 `data/dataset/<asset>/`。路径在 `config/application.json` 中配置，也可用 `uv run --frozen stockregression set-data-dir D:\market\stockregression-data` 修改；相对路径按项目根目录解析。业务参数不再由环境变量覆盖，`STOCKREGRESSION_HOME` 只定位项目。

| 路径（相对 `data/`） | 内容 |
| --- | --- |
| `catalog.sqlite` | 证券、自选、快照索引、共享辅助资料、逐项同步检查点、配置与任务 |
| `.stockregression/manifest.json` | 数据包身份、版本和文件清单 |
| `.stockregression/history/` | 原子更新前的物理文件版本 |
| `.stockregression/quality/` | 覆盖与质量检查报告 |
| `.stockregression/staging/` | 上传和待发布文件 |
| `catalog.sqlite` 的 `parquet_*` 表 | 版本文件清单、覆盖、导入指纹和质量报告 |
| `dataset/etf/` | 当前 ETF 行情数据包 |
| `dataset/stock/` | 股票行情数据包（预留，与 ETF 使用相同布局） |
| `imports/<周期>/` | 文件批量导入的默认投放目录 |
| `etf_*`、`stock_*` | 数据包内日线集中文件和分标的分钟、周线、月线文件 |
| `results/` | 完整回测、研究和同步报告 JSON |
| `logs/` | 失败任务的完整异常记录 |

导入、同步、读取和回测共用同一套价格校验。`0`、负值、空值、`NaN`、无穷值及不符合高低价关系的 OHLC 会从浏览数据中隔离并进入质量报告；相关区间不会自动补价，严格回测和研究返回 `DATA_NOT_READY`。图表在该缺口处断开均线，零成交量也不会被当成停牌。

请备份当前数据包；catalog.sqlite 是可重建索引，策略配置、任务和结果仍保存在应用数据目录。`paths.package_dir` 写入 `config/application.json`，修改后重启生效。整个数据包可以搬移，索引记录使用包内相对路径。

## 模型与覆盖限制

- 真实收盘产生网格信号，后续真实开盘执行；合成条不触发成交，开盘封板保守拒单。日线降级不能恢复盘中路径。
- ETF 按资料中的类型使用 0.001 元精度、100 份单位、对应涨跌幅和 T+0/T+1；ETF 不套用股票印花税和股票过户费。分类推断应结合证券资料核对，导入可覆盖类型。具体口径和来源见[回测规则](docs/rules.md)。
- 分红按税前计入；拆分与合并自动按接口倍率及本地行情处理；仅缺少计算必需数据、配股等无法结算的事件阻止相关区间回测，资料核验标记不单独拦截。
- 股票早期过户费不完整年份采用明确估算；不会将当前费率静默套到所有历史。训练和测试结果仅反映所用数据与模型。

验收范围、联网来源检查与限制见[验收记录](docs/validation.md)。运行检查：`uv run --frozen pytest -q`，以及 `frontend` 目录下的 `npm test`（Node.js 24）和 `npm run build`。

### 联动参数与自动计算

`parameter_links.spacing` 与 `parameter_links.shares` 默认均为 `false`，分别约束买卖间距及份额相等。联动后的研究范围和粒度须一致；新结果记录版本化的自由轴元数据，候选与导出仍保留四个执行字段。训练候选按自由维数显示二维热力图、可旋转缩放的三维散点，或固定第四参数的三维切片。图中只展示实际归档评价，切片先在存储端过滤再抽样，颜色范围跨切片保持一致。

自动预览与研究预估共用 `ui.preview_debounce_ms`，默认 1500 毫秒。连续编辑只保留最新待计算参数，旧代次可协作取消；手动提交的正式回测、研究和补算继续使用提交时的冻结参数。研究预估只依赖影响数据、空间和预算的设置，费用、定投、评分权重等改动不会重复读取历史。
