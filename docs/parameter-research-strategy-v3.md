# 历史参数研究策略（v3）

> 历史资料：本文描述 `protocol_version=4`、`strategy_version=3` 的旧超正方体平均超额方法。该协议和兼容入口已移除；当前契约见[参数研究 v5](parameter-research-v5.md)。

本文记录项目当前 `protocol_version=3` 的参数研究实现，描述程序实际执行的流程、资格门槛和结果解释。适用于 `schema_version=3` 配置。v1/v2 历史结果沿用各自原有计算口径，不由本文重新定义。

## 先看流程

```text
按决策日截取此前行情
  → 取最多 504 个交易日
  → 前 252 日形成统计画像和局部搜索组合
  → 训练评分后冻结最多 10 个验证中心
  → 加入每个中心的单参数及双参数邻点
  → 后 252 日分成四个连续验证窗，并在两种成本下计算
  → 先应用中心硬约束，再判断双成本邻域稳健性
  → 有合格中心时给出推荐；否则 recommendation_status=no_qualified
```

历史数据严格截止于决策日收盘。固定方案在评估期开始前选一次参数；自适应方案按 `rebalance_days` 交易日间隔重新选择，默认 63 日，并从下一交易日生效。选择“固定与自适应”时，两条流程共用同一套研究协议，但各自按当时可用历史形成决策。评估期末还会单独计算一次“当前参数”，该结果是研究诊断，不会倒灌到之前的交易。

## 协议与默认设置

| 设置 | 当前默认值 | 实际作用 |
|---|---:|---|
| 协议 | `protocol_version=3` | 使用统计中心和局部网格，不使用旧版 TPE 试验生成器 |
| 搜索配置 | `schema_version=3` | 最高持股可为空；不接受固定可用现金预算 |
| 历史回看 | 504 个交易日 | 完整研究窗口及正式推荐的最低历史要求 |
| 画像／训练段 | 252 个交易日 | 形成统计中心并为局部组合打训练分 |
| 验证段 | 252 个交易日 | 切为四段连续验证窗，每段目标约 63 个交易日 |
| 自适应重选 | 每 63 个交易日 | 可由研究设置调整 |
| 局部搜索预算 | 3000，配置上限 5000 | 超预算时预检并停止提交，不会静默截断搜索 |
| 成本情景 | 原始成本、双倍佣金／最低佣金／滑点 | 两种情景都要满足推荐门槛 |
| 邻点正超额比例 | 至少 80% | 分别对两种成本情景计算 |
| 邻点分位数 | 第 25 百分位大于 0 | 分别对两种成本情景计算 |
| 最大回撤约束 | 20% | 默认值，可调整 |
| 最少成交 | 10 笔 | 默认值，可调整；在验证窗中按成本情景累计统计 |
| Bootstrap | 10,000 次 | 默认值，可调整；块长 20 日为主，并报告 10／40 日敏感性 |

默认参数搜索区间如下，用户配置是每次研究的硬边界，实际研究会使用提交时保存的范围：

| 参数 | 默认下限 | 默认上限 | 搜索步长 |
|---|---:|---:|---:|
| `buy_step`、`sell_step` | 0.5% | 10% | 0.5 个百分点 |
| `buy_shares`、`sell_shares` | 100 股／份 | 1000 股／份 | 100 股／份 |
| `min_shares` | 0 股／份 | 1000 股／份 | 100 股／份 |
| `max_shares` | 1000 股／份 | 5000 股／份 | 100 股／份 |

所有网格模式都使用 `buy_step` 和 `sell_step`，两者分别控制参考价下方和上方的网格。初始持股由配置固定，不参加搜索。若 `max_shares=null`，该值保持为空且最高持股维度完全退出搜索和邻域评价。

v3 的 `n_trials`、旧 `mode` 等兼容字段不会把搜索切回 TPE；v3 实际采用 `local_search_budget`。前端的候选展示上限只限制页面显示行数，不减少实际验证的候选族。

## 历史窗口与时间隔离

每次选择参数时，程序只看决策日及此前的行情，并最多取最后 504 个交易日：

- 有完整 504 日时，前 252 日是生成／训练段，后 252 日切成四个连续验证窗。
- 有 168–503 日时，历史大致对半切成生成段和验证段，并把后半段分成最多四窗；结果可用于探索和相对比较，但因不具备完整 504 日历史，不能成为正式推荐。
- 少于 168 日时，全部历史用于探索性回看，没有分离的验证窗，也不报告显著性结论；同样不能成为正式推荐。

四窗使用同一批冻结参数，窗口结束后不会用后续数据改写之前的中心、参数或成交。评估期的自适应流程则在各个重选日重新运行完整的当期选参流程，只使用此前已收盘数据。

## 统计画像与中心生成

统计画像只从生成／训练段的有效日线计算，并以 `preclose` 处理公司行动带来的参考价变化。主要统计量包括：

```text
日内上行幅度 = max(high - open, 0) / open
日内下行幅度 = max(open - low, 0) / open
真实波幅     = (max(high, preclose) - min(low, preclose)) / preclose
日涨跌       = close / preclose - 1
```

程序分别取上行幅度、下行幅度和真实波幅的 25%、50%、75% 分位数。对每个分位数生成一个候选步长中心，最多三个，重复中心会合并。所有网格模式中，下行分位数映射到买入间距，上行分位数映射到卖出间距；固定网格的向下和向上分区分别使用这两个间距。

还会计算对数收盘价年化趋势斜率，以及下跌交易日之后固定五个交易日的累计修复收益中位数。五日修复观察不能越过生成段终点。趋势和修复数据用于描述行情环境，不单独决定推荐资格或未来收益。

步长设置有交易成本下限：

```text
下限 = max(2 × 估计往返交易成本率, 2 × 最小价格档位 / 生成段收盘价中位数)
```

往返成本估计复用当前手续费、最低佣金、税费及滑点配置。统计分位数低于该下限时会抬高到下限，再按用户搜索刻度对齐。若用户搜索区间无法容纳达到下限的合法刻度，该统计中心会被拒绝，并把原因保存在画像诊断中；程序不会扩大用户设定的范围。

数量边界和单次买卖数量不由行情波动推断资金承受能力。它们以基础配置为中心，在用户设定范围内接受后续局部搜索。持股数按合法数量单位对齐，且必须满足最低持股不高于固定初始持股、最高持股不低于固定初始持股以及最低持股不高于最高持股。

## 局部搜索与验证中心

每个统计中心对每个有效搜索维度取“中心值、低一步、高一步”，构成局部笛卡尔网格。范围边界会裁剪坐标；相同组合去重，非法持股组合剔除。各参数的步长使用用户显式设置的搜索步长；未设置连续参数步长时按搜索范围宽度的 5% 取步长；股数步长至少为 100 股／份。

预检的预算按各统计中心局部笛卡尔网格数量求和后检查，重叠组合在实际训练前再去重。因此预估数可能大于最终唯一组合数。超过预算时返回 `SEARCH_BUDGET_EXCEEDED`，要求调整搜索范围或预算，不会改用另一套搜索算法。

训练段为每个局部组合计算：

```text
训练超额收益 = 网格峰值本金收益率 - 同期独立全仓持有收益率
训练分       = 训练超额收益 - 训练段资金流调整最大回撤
```

对每个统计中心，先保留其来源组合中训练分最高的合法点。然后按训练分从高到低补充不同区域的组合，最多形成 10 个验证中心；补充中心之间按搜索步长归一化后的参数距离至少为 2。此训练分只用于决定进入验证的中心，不是推荐资格或统计显著性证明。

基础配置会作为研究对照加入候选族。它不因相对表现较好而取得推荐资格；若它与某个搜索中心重合，重合候选仍标记为基线，不获得推荐资格。若统计中心没有可搜索的合法组合，系统保留基线用于对照并记录原因。

## 候选邻域怎样构成

验证前冻结验证中心、候选编号和邻域。对每个中心，程序生成：

1. 每个有效维度分别向正、负方向移动一步的单参数邻点。
2. 每一对有效维度同时向正／负方向移动一步的四种组合。

不变维度和 `max_shares=null` 不参与扰动。若有 `d` 个可变维度，理论邻点数为 `2d + 4 × d(d−1)/2`；六个有效维度时最多 72 个，中心本身不计入邻点统计。范围边界上的扰动会裁剪到范围端点，重合点去重，因此实际邻点数可以小于理论值。结果同时记录理论期望数量、实际邻点及是否发生边界裁剪。

推荐检查的是每个中心关联的所有不同合法邻点。每个邻点都必须在原始成本和压力成本下完成验证；任何失败、取消或缺失都使该中心的邻域评价不完整，不能通过剔除未完成点来提高正收益比例。没有真实邻点时状态为“无法评价邻域稳健性”。

## 验证指标与推荐门槛

比较基准是独立全仓持有账户，包含公司行动和股息。v3 使用其每日收益与网格账户逐窗对齐。每个验证窗分别计算网格峰值本金收益率及同期全仓持有收益率：

```text
E_k = 网格在第 k 窗的峰值本金收益率 - 同期全仓持有收益率
跨窗稳健超额 = median(E_1…E_4) - 0.5 × IQR(E_1…E_4)
```

窗口本金只用该窗口开始时资产及该窗口内新增补款核算，不使用之后窗口的投入。中心和每个邻点都分别在原始成本、双倍佣金／最低佣金／滑点压力情景下计算该跨窗稳健超额收益。税费按原有规则处理。

一个候选中心只有同时满足下列条件才进入推荐序列：

1. **中心有正超额：**跨窗稳健超额收益在两种成本情景下都大于 0。程序要求四窗数据和成本情景完整，但不要求每个单独窗口都为正。
2. **邻点正超额比例达标：**不含中心自身，至少 80% 的不同有效邻点跨窗稳健超额大于 0；原始成本和压力成本分别计算，二者都要达标。正好为 0 的邻点计入非正一侧。例如 5 个邻点至少 4 个为正，9 个邻点至少 8 个为正。
3. **邻域下四分位为正：**不含中心自身，邻点超额收益第 25 百分位在两种成本情景下都大于 0。
4. **中心满足硬约束：**两种成本下所有验证窗观测到的最大回撤不超过配置上限；每种成本下四窗合计成交数不少于配置下限；验证期间都至少发生过一次买入及一次卖出。
5. **研究完整：**全邻域、两种成本及四窗均成功完成，并具备完整的 504 日选择历史。
6. **中心不是原始基线：**基础配置仅作对照，不参与正式推荐。

其中正超额比例按不同邻点的数量计算，第 25 百分位按邻点得分分布计算；两项都不包含中心自身。边界裁剪去重后按实际不同邻点计算。没有完整的 504 日历史、没有实际邻点或邻域结果不完整时，即使已计算部分结果看起来很好，也不会授予推荐资格。

## 推荐排序、孤岛标记和暂停行为

合格中心排在所有不合格中心之前，并按下列顺序稳定排序：

1. 两种成本下较差的邻域超额收益第 25 百分位，越高越优。
2. 两种成本下较差的中心跨窗稳健超额收益，越高越优。
3. 较低的验证期最大回撤。
4. 较低的峰值净投入。
5. 较小的候选编号。

若没有任何中心合格，`recommended_params` 为空，`recommendation_status` 为 `no_qualified`。结果中仍可能有 `params` 或 `diagnostic_params`，它们表示相对最佳研究对照，不能当作推荐参数。

当前“疑似收益孤岛”标记要求中心在两种成本下跨窗稳健超额都为正、邻域已完整计算，而且原始成本下正超额邻点比例大于 0 但低于 50%。该标记表示收益集中在少数参数点；它不是对噪声成因的统计证明。标记计算当前使用原始成本下的邻点比例，双成本推荐门槛仍然分别执行。

无合格推荐时固定方案在评估期不执行网格交易，账户原有持仓继续计价。自适应方案该决策记录为暂停，不提交网格单，保留现金、持仓及公司行动处理；后续某次重选通过后，从该决策的生效日恢复，不回补暂停期间信号，也不强制清仓。

## 统计证据与热力图

“邻域稳健性通过”与“统计显著性得到支持”是两个独立结论。当前参数族的内部统计诊断使用已冻结的完整候选族、原始成本日收益和独立全仓持有收益，执行配对 stationary bootstrap／White Reality Check 家族校正。每日按所有候选共享的区块重抽样，以保留时间相关性及候选之间的相关性。默认 10,000 次、平均块长 20 日为主结果，并计算块长 10 日和 40 日的敏感性结果。这个内部验证段已经参与了候选筛选，记录为 `internal_validation_used_for_selection`，`independent_oos=false`；它不改变已经选出的参数，也不替代邻域门槛。

此外，结果报告末 126 个评估交易日中固定／自适应流程的实际连续回测轨迹，并与同期独立全仓持有收益配对检查。这个流程级检查与“当前参数”的末日重选结果分开。样本不足 126 日时会明确标记区间不足。Bootstrap 的 p 值表示家族零假设检验结果，不是策略未来获胜概率。

结果页的“参数收益分布”提供：

- 二维参数切片：选择两个有效参数作为横纵轴，其余参数固定在所选中心；切换训练／验证、决策日、验证窗、成本情景，以及超额收益／网格收益。
- 缺失状态：未计算、非法、失败等状态保留为空或标注状态，不插值成零收益。
- 参数切片：默认显示买入间距 × 卖出间距，也可选择其他二维参数平面。点击候选可查看实际参数及其邻点。

热力图颜色用于观察候选收益分布，不改变候选资格、邻域定义和推荐排序。邻点关系始终按原始参数空间中的用户搜索步长确定。

## 数据质量、接口和版本兼容

分钟覆盖率低于配置要求时会在研究结果中给出数据质量提示，但系统仍可提供相对排名；它不是 v3 邻域推荐资格的硬门槛。行情估值、价格或公司行动等硬错误仍可能阻止计算。日线研究结果应按日线模拟精度解释，不能据此宣称已还原分钟级成交顺序。

v3 研究结果会保存统计画像、统计中心、局部组合来源、验证中心、邻域计数、双成本指标、推荐状态及计算量。默认研究摘要不传输完整候选矩阵；参数收益分布通过 `GET /api/v1/results/{result_id}/landscape` 按需读取。v3 搜索预检通过 `POST /api/v1/optimizations/preview` 返回统计中心和预计组合数。直接提交旧 schema/protocol 的新执行请求会要求先转换配置；旧结果仍按其原始版本展示和导出。

## 结果解读清单

看一项研究时，建议按这个顺序核对：

1. `protocol_version` 是否为 3，历史数据截至日和 504 日窗口是否符合预期。
2. 统计画像有没有被拒绝的中心，拒绝原因是否由成本下限或搜索区间导致。
3. `local_search_expected`、`local_search_unique` 和 `local_search_budget` 是否合理。
4. 每个推荐中心是否完成全部邻点与双成本计算，实际邻点数是否因边界裁剪减少。
5. 两种成本下的中心稳健超额、正邻点比例及邻域第 25 百分位是否都过门槛。
6. `recommendation_status` 是 `qualified` 还是 `no_qualified`；若无推荐，区分推荐字段和相对最佳诊断字段。
7. 分开读取内部家族检验、末 126 日流程检验、峰值本金收益和资金流调整风险指标。

该协议的目标是减少对尖锐参数峰值的依赖，并提高研究过程的时间隔离、可复现性与结果可解释性。邻域平坦或局部超额为正只构成筛选证据，不保证未来盈利，也不代替策略逻辑和交易成本的持续复核。
