# ETF 网格研究

“ETF 研究”先对本地 ETF 做横截面适用性诊断，再用当前分钟成交内核回放有限的参数候选。默认范围为自选 ETF，窗口 120 个交易日，可改为 250 日；默认核验评分最高的 10 个合格标的。初始持股、持股限制、每笔买卖份数与费用取自回测草稿，提交后冻结。

## 从预检到结果

1. 选择自选、本地全部或指定 ETF，设置截止日和窗口，运行预检。
2. 待核验区间可提交“本地批量校验”。校验只使用本地数据，不下载行情；完成后重新预检。任务中心可打开保存的逐标的校验报告与失败原因。缺失行情、未核实分红或无法校准的来源需要到数据管理处理。
3. 提交研究后，任务先冻结候选列表和逐标的数据快照，再逐个计算统计量、完成横截面排名，并回放前若干名的步长候选。
4. 排名行可展开指标原因、费用与成交结果。未进入自动核验范围的 ETF 可以单独提交核验；单标的结果保留指标与候选，横截面分数为空。

默认截止日取候选池中已有分钟数据能达到的最新已收盘日期，滞后标的单独报告。显式指定截止日后，缺口不会被更早数据悄悄替代。数据集目录中的 `ready` 不代表任意研究区间都已通过质量账本。

增量同步的辅助日历可能只含最近几天。预检会将它与锁定版本的日线日期索引合并，再计算完整交易日窗口；日历条数不会被当成全部行情历史。此过程只读取日线时间列，不扫描分钟行情正文，区间质量仍需独立通过本地校验。

## 方法版本和价格口径

当前方法为 `etf_min_grid_v1`，独立结果格式为 `result_schema_version=1`。普通回测继续使用 `schema_version=3`，稳健 J 研究继续使用协议 v5。

统计价格以截止日已实施的公司行动统一到截止日基准；份额折算同步调整历史成交量，现金分红不改变成交量。分析不读取截止日之后的价格或除权事实。回放账本仍使用真实未复权价格及权益处理，参考价与上下轨在除权时同步调整。

成交分布是 200 桶的分钟 OHLC4 成交量分布近似，不是逐笔成交或实际持有人筹码分布。同花顺分钟成交额是 OHLC4 估算后按官方日成交额缩放，结果会记录成交额来源和估算质量。

| 指标 | 口径 |
| --- | --- |
| RV | 分钟日内收益平方和，按 252 日年化；附 5 分钟对照 |
| PR | 分钟完整价格路径冗余度，包含真实隔夜位移 |
| IOVR | 日内方差与开盘相对前收盘的隔夜方差之比 |
| VR | 5 分钟基频，60/240/1200 交易分钟尺度的描述性方差比 |
| OU | 30 分钟 AR(1)，只在同日连续时段内形成相邻拟合配对 |
| ZCR | 5 分钟价格相对过去 5 日均线的过零率 |
| JR | 5 分钟日内 RV/BV 跳跃占比，BV 不跨午休、隔夜和缺失段 |
| MDDD | 独立 250 日日线窗口的最长水下持续期，注明期末未恢复状态 |
| TPR | 最小价格单位 / 最近 20 日未复权均价 |

OU 仅在 `0 < φ < 1` 时输出参数，半衰期为 `ln(2) / (8 × -ln φ)` 个交易日，稳态标准差为 `σ残差 / sqrt(1-φ²)`。这是模型拟合诊断，不构成平稳性或获利能力的统计证明。零分母、历史不足或无效模型均输出空值及原因。

GSS 使用同一截止日、同一窗口候选池的平均秩百分位，权重为 RV 25%、PR 20%、反向 VR240 20%、IOVR 15%、ZCR 10%、反向 JR 10%，总分为 0–100。少于两个完整评分样本时不输出分数。排名记录实际参与的标的池，不能把不同池的分数当作绝对等级比较。默认适用性过滤为无有效 OU 模型、VR240 超过 1.10 或近期均价低于 0.5 元。

## 参数候选和样本内回放

成交分布峰值、分位数与 OU 估计融合为参考价和上下轨。步长下界取 30 分钟波幅下限与 Tick 下限的较大值，向上按 0.1 个百分点步进至 5%。每个基准保留对称候选；偏度和半方差比一致时再加入非对称候选，倍率上限为 1.6。价格越界、Tick 重复或无有效网格时报告原因。

每个标的最多回放约 100 组候选。使用与正式回测相同的收盘信号、次根真实开盘成交、T+1、最低佣金、滑点、整数份额和补款规则。默认资格为成交至少 10 次、买卖两向均发生、本金回撤不超过 20%、网格收益与同资金配对超额均为正。合格候选按配对超额、较低回撤、较低费用和确定的参数顺序排列。

自动回放属于样本内参数核验，结果保留选参截止日和使用窗口。找不到合格候选时返回 `no_qualified`，候选和拒绝原因仍可查看。GSS 与样本内收益分开呈现，不生成稳健 J 分数或预期年化收益。

“复现核验回测”携带冻结的历史配置及行情版本。原版本被清理时明确失败，不改用当前行情。“创建后续回测草稿”使用截止日原始价格基准，开始日在截止日之后；无后续行情时仅建立草稿。载入动作不改写本机默认设置。

## API 与任务

- `POST /api/v1/etf-research/preflight`：读取目录、辅助资料及质量账本，返回逐标的预检状态。
- `POST /api/v1/etf-research/validation`：提交 `etf_validation` 本地校验任务。
- `POST /api/v1/etf-research`：冻结预检结果并提交 `etf_research` 任务。
- `POST /api/v1/etf-research/{id}/validate/{symbol}`：沿用原结果的价格、辅助资料、股数与费用，对该 ETF 单独核验；原版本不可用时拒绝改用当前版本。
- `GET /api/v1/results?kind=etf_research`：分页列出研究历史。
- `GET /api/v1/results/{id}`：读取不含行列表的摘要。
- `GET /api/v1/etf-research/{id}/items?offset=0&limit=50&symbol=159611.SZ`：读取分页行或指定 ETF 的详情。
- `GET /api/v1/results/{id}/export?kind=json`：导出完整结果。
- `POST /api/v1/backtests?version=...`：以指定顶层快照提交回测；省略版本沿用普通回测行为。

三个 POST 共用独立请求契约：`scope`（`watchlist/local/selected`）、`symbols`、`as_of`、`window_days`（120/250）、`validation_top_k`（0–100）、`execution`（股数和费用模板）、`min_trades`、`max_principal_drawdown`、`max_runtime_seconds` 和可选配置修订号。显式代码使用 `selected` 范围。默认时间预算为 3600 秒，沿用本机 CPU 与工作集限制。

任务记录统一候选清单、包身份与代际、逐标的顶层版本、内部行情和辅助版本、配置及计算来源。通过的质量区间连同校验规则版本、行情和辅助资料依赖一起写入不可变快照，因此后续同步更新当前账本时，历史快照仍使用原质量凭证。凭证不会覆盖新增行情或其他版本。排队中的本地校验若发现输入已经改变，会提示重新预检。取消、超时或数据代际变化会保留已完成的指标或候选；统计阶段未完成时不发布完整排名。读取和导出不会触发计算、校验或下载。
