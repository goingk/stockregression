# 本地行情文件格式

本页说明单文件导入和文件夹批量导入接受的 CSV / Parquet 格式。正式导入只接受基础周期 `1min` 和 `1day`；`5min`、`15min`、`30min`、`60min` 由 1 分钟聚合，`1week`、`1month` 由日线聚合。旧数据包中的粗周期文件仍可登记用于追溯，但不会作为新查询的兜底来源。支持沪深 A 股和场内 ETF，数量单位分别为股和份。样例块只列出表头，不含价格或成交量样本。请导入真实、未复权、时间和单位可核验的数据。

## 导入命令

CLI 要求明确指定证券、基础周期和文件路径：

```powershell
uv run stockregression data import-file 600000.SH --frequency 1day --path .\daily.csv `
  --actions-path .\actions.csv --calendar-path .\calendar.csv
uv run stockregression data import-file 600000.SH --frequency 1min --path .\minute.csv `
  --calendar-path .\calendar.csv --label-convention end
```

文件扩展名为 `.parquet` 时按 Parquet 读取；其他扩展名按 CSV 读取。CLI、网页和 API 都在运行程序所在的本机读取该路径，不会上传到远端处理。

`data import-file` 和 `data import-folder` 使用 `--import-mode merge|snapshot`。`merge` 默认保留历史并只写入新增或修订分片；`snapshot` 以本次全量文件为当前底座，缺失的旧日期会退出当前视图，旧版本仍可追溯。

若 Parquet 把 K 线时钟放在索引而不是列里（例如 Tushare 导出的 `trade_date` / `trade_time` 两级索引），导入器会把日期时间索引层级提升为列后再按上表别名识别，不需要事先 `reset_index`。索引中的其他层级会作为普通列保留。

示例假定分钟时间戳是结束标签，因此写了 `--label-convention end`；若供应方给的是开始标签，应改为 `start`。不确定时省略该选项，默认值 `auto` 会尝试校准，未核验的交易日按日线处理。请根据数据源说明选择标签，不要仅凭文件中时间看起来接近收盘就判断。

`data import-file` / `data import-folder` 不自动联网，也不读取其他周期。分钟文件缺少日线、真实交易日历或标签依据时仍可入库，但会标明待核验和不能严格回测的原因。需要回测时，应分别导入或显式同步日线、辅助资料和对应分钟周期。

## 日线

必需行情列为日期、开盘、最高、最低、收盘和成交量。严格回测还要求原始文件明确提供 `preclose`、`tradestatus`；股票额外要求 `is_st` 或 `isST` 历史字段，ETF 不要求 ST 字段。这些准确性字段不由导入器推算。缺少字段时数据可以保存和浏览，但数据集会标记不能严格回测。

ETF 导入可通过网页类型选择，或 CLI `--etf-category stock|bond|crossborder|commodity|money` 覆盖证券清单识别结果，分别对应股票、债券、跨境、黄金/商品和货币 ETF。股票可忽略该选项。ETF OHLC 按 0.001 元精度、成交量按份提供；如果来源的成交量单位为手，须先正确转换，不能把手数直接当份数。

```powershell
uv run --frozen stockregression data import-file 518880.SH --frequency 1day --path .\etf-daily.csv --calendar-path .\calendar.csv --actions-path .\etf-actions.csv --etf-category commodity
```

ETF 分红资料未核验的区间不能严格回测。可提供经核实的公司行动文件（确认无行动时使用带规范表头的空文件），切勿为了绕过核验而伪造空资料。

| 含义 | 规范列名 | 可识别的别名 / 说明 |
| --- | --- | --- |
| 交易日期 | `date` | 也可用 `timestamp`、`datetime`、`day`、`dt`、`time`、`trade_date` 或中文 `日期`；按日期归一化。 |
| 开盘价 | `open` | 或 `开盘` |
| 最高价 | `high` | 或 `最高` |
| 最低价 | `low` | 或 `最低` |
| 收盘价 | `close` | 或 `收盘` |
| 成交量 | `volume` | 或 `vol`、`成交量`；单位须与分钟文件一致并按股数提供。 |
| 前收盘 | `preclose` | 准确导入必需。应提供真实未复权交易前收盘，不能用前一条记录的收盘值取代除权参考价。 |
| 交易状态 | `tradestatus` | 准确导入必需；`1` 为正常交易，`0` 为确认停牌。状态未知不要伪填为 `1`。 |
| ST 历史状态 | `is_st` 或 `isST` | 准确导入必需；建议用 `0`/`1`，分别表示否/是。 |
| 股票上市日期 | `listing_date` | 可选；如数据源能提供，可在每行重复填写该股票的实际上市日期（`YYYY-MM-DD`），用于识别上市初期交易规则。 |
| 成交额 | `turnover` | 可选，也可用 `amount` 或 `成交额`。 |

CSV 表头格式（不含历史行情行）：

```csv
date,open,high,low,close,volume,preclose,tradestatus,is_st,listing_date,turnover
```

日期应覆盖与交易日历相交的全部交易日，包括停牌日；停牌时仍需有日线价格和 `tradestatus=0`，以便后端明确识别停牌，而不是把缺日当成未交易或缺失。状态列和 OHLCV 数据应是同一股票、同一未复权口径。

## 分钟线

5/15/30/60 分钟可以分别独立导入并直接供相同周期回测使用；只有当本地存在 1 分钟数据且回测请求其他分钟周期时，兼容读取路径才会重采样。导入 15 分钟文件不会生成或下载 1 分钟数据。

自动标签核验可复用本地已验证分钟或已缓存的独立 5 分钟参考行情。已存在但待校准的分钟数据不再触发历史下载；预览将其与真实分钟缺口分别提示。结束标签文件若单独提供 09:30 集合竞价记录，会将真实 OHLC、成交量及成交额合入 09:31 首根 K 线，避免丢失竞价成交；开始标签的 09:30 记录仍按首根连续交易分钟处理。价格比较容忍微小浮点误差，明显的高低价矛盾仍会拒绝分钟模式。

| 含义 | 规范列名 | 可识别的别名 / 说明 |
| --- | --- | --- |
| 分钟时间 | `timestamp` | 也可用 `datetime`、`day`、`dt`、`time`、`trade_time` 或中文 `时间`；日线式 `date`、`trade_date` 也可映射，但分钟记录仍必须带具体时分。 |
| 开盘价 | `open` | 或 `开盘` |
| 最高价 | `high` | 或 `最高` |
| 最低价 | `low` | 或 `最低` |
| 收盘价 | `close` | 或 `收盘` |
| 成交量 | `volume` | 或 `vol`、`成交量`。单位应与日线成交量一致；后端会测试 1 倍与 100 倍候选并记录校准结果。 |
| 成交额 | `turnover` | 可选，也可用 `amount` 或 `成交额`。 |
| 来源 | `source` | 可选，仅作来源标识。 |

分钟 CSV 表头格式（不含历史行情行）：

```csv
timestamp,open,high,low,close,volume,turnover
```

时间可以带时区；如带时区，导入器先转换到 `Asia/Shanghai`，再去掉时区标识用于本地交易时段校验。请保证源数据实际对应上海市场时钟。分钟记录的开盘、最高、最低、收盘必须为正；出现 0 或负值的文件会被整帧拒绝，因为非正价格是来源缺陷，不是真实成交。默认 `label_convention=auto` 会保留原时间并标记待核验，不会猜测平移。数据供应方已明确标签定义时，可选择 `end`（K 线时间是结束时间）或 `start`（K 线时间是开始时间，导入器按所选周期长度平移到结束标签）。之后也可在数据管理页确认标签，在本地重新校验，无须重新导入文件。选择前请核对数据源说明；选错标签可重新确认，或在严格回测中回退到日线。

## 交易日历

日历文件必需包含一列 `date`，每个真实沪深交易日一行。表头格式：

```csv
date
```

未提供交易日历时，新的本地导入不会联网获取；数据可以保存，但会标记覆盖检查受限、待核验。显式线上同步日线可以同时取得真实日历。不要用 `pandas.bdate_range`、周一至周五序列或未经核实的日期列表替代交易日历，否则节假日、停牌日及上市区间判断会不准确。

## 公司行动（分红、送转等）

有现金分红或送转的真实未复权价格序列应提供覆盖研究区间的公司行动资料。公司行动文件可选，但若除权前收盘变化没有对应的公司行动，回测会因无法解释跳变而拒绝运行。提供文件时至少要能归一化为下列字段：

| 规范列名 | 含义 | 要求 |
| --- | --- | --- |
| `record_date` | 股权登记日 | 必需。 |
| `ex_date` | 除权除息日 | 必需。 |
| `pay_date` | 现金红利派息日 | `cash_per_share > 0` 时必需。 |
| `stock_date` | 送转股可交易日 | `bonus_ratio > 0` 时必需。 |
| `cash_per_share` | 每股现金红利 | 可为 0；供应方 BaoStock 字段 `dividCashPsBeforeTax` 表示税前金额。 |
| `bonus_ratio` | 每股新增股份比例 | 可为 0；供应方的送股与转增比例会合并为该字段。 |
| `implemented` | 是否确认已实施 | 必需事件需为真。CSV 建议用数值 `1`/`0`，避免将字符串 `"False"` 误读为真值。 |
| `unsupported_reason` | 未建模事项说明 | 可选；非空时后端会阻止回测。 |

文件列名支持部分 BaoStock 分红字段别名：`dividRegistDate`、`dividOperateDate`、`dividPayDate`、`dividStockMarketDate`、`dividCashPsBeforeTax`，并可从 `dividStocksPs` 和 `dividReserveToStockPs` 合并送转比例。推荐自行转换为规范列名，确保字段完整、日期语义明确。

公司行动 CSV 表头格式（不含历史公司行动行）：

```csv
record_date,ex_date,pay_date,stock_date,cash_per_share,bonus_ratio,implemented,unsupported_reason
```

现金红利是税前值；本版不计算个人所得税。配股、合并、拆股等未建模的特殊公司行动会阻止相关回测。不能确认是否实施或缺少必要日期时，应先完善公司行动数据，不要填造日期以绕过校验。

## 分钟质量核验与回测降级

后端使用每个交易日 240 个分钟估值位置：上午 `09:31–11:30`、下午 `13:01–15:00`，均按结束标签记时。这是对齐网格，不表示每个位置都应有实际成交。校准档案会记录 `convention`、`volume_multiplier`、`verified_days`、交叉源匹配分数和原因。时间标签/单位未核验时，页面仍保留档案信息，但该交易日不会用未验证分钟价格路径，回测会改用日线。

深交所收盘集合竞价为 `14:57–15:00`，于收盘集中撮合。对于 `2023-02-17` 起的深市记录，只有已校准的 `14:57`、`15:00` 原始记录均存在时，缺少的 `14:58`、`14:59` 才归为集合竞价估值占位，单列 `auction_placeholders`，不计为实际行情缺口或修复。占位以前值记价、成交量为零，不产生交易；已有的任何原始竞价记录均保留。5/15/30/60 分钟聚合中的这些占位不会使真实收盘成交失效。其他日期、市场、缺少收盘锚点或未校准来源仍按普通缺口核验。规则依据见[深交所交易规则 2.3.2、3.4.1](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。

对于分钟档案通过校验的交易日，最多允许整日缺 5 根且每个交易时段中连续缺失不超过 3 根；上午和下午首分钟必须存在。后端还会验证 OHLC 合法性、分钟成交量与日线总量，以及完整日的收盘、最高、最低价与日线是否一致。少量合格缺口只以前值补价格、成交量置零，并标记 `is_synthetic`；这种合成分钟不能发起交易。超过阈值、首分钟缺失、价格/成交量不一致或来源未校准时，数据仍可浏览和继续修补，但本次目标周期的质量报告会标为不完整，严格回测返回 `DATA_NOT_READY`。价格为 `0`、负值、空值、`NaN`、无穷值或高低价关系错误时，该记录直接隔离，不参与任何补价；读取与计算共用这一规则。旧格式快照兼容已移除。

当前质量以本地合并后的真实记录及请求区间的核验结果为准，手动导入和接口同步的日期、行数分别列出。`diagnostics` 区分分钟保留率、原始有效交易分钟缺失、实际修复和集合竞价占位；100% 分钟保留率不代表所有分钟均为原始记录。历史接口失败和来源覆盖限制保留在 `source_events`，不再作为已被本地导入补齐后的当前缺口。不可变快照和当前结果保留原始内容；派生校验缓存随质量规则版本失效，不以旧摘要替代当前核验。

日线降级只提供每日 OHLC，不能重建盘中先后顺序或网格触发点。因此分钟覆盖率不足时，不能把这类日线降级回测当成分钟策略完整执行结果。
